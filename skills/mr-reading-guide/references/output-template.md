# 阅读指南输出骨架

这是可裁剪的 Markdown 骨架。正文讲决定与流程，表格承载证据账本。简单变更合并章节，相关的重点才使用详细卡片。

## 对象与结论

- 分析对象、需求来源、base/head、获取时间；本地差异另写快照标识。
- diff 是否完整，阅读/运行范围，已知缺口；已确认需求和当前实现差异。
- 一句话描述触发场景以及旧行为 → 新行为。

## L1：先看这些决定

默认最多 3 项。每项用短段说明：选择是什么、为什么值得人看、带来的收益或约束、下一层与代码入口。

高后果未决事项在此提示，即使需要超出默认项数。

## L2：沿主链路建立理解

默认最多 7 个主题，按行为顺序连接，关联 L1。

用文字、伪代码或一张必要的流程/时序/状态图表达入口、参与者、关键数据变化、结果和相关失败。图可用 Mermaid；图里的每条实线关系必须有实现证据，推断与提议明确区分。

## L3：重点的证据与细节

每个重点按需包含：

**D01 — 一个可以回答的设计问题**

- 当前选择、责任模块、适用条件。
- 原理 → 本次代码事实 → 判断；事实/需求/推断/未知分开。
- 已复用能力；相关替代方案、收益、代价和何时值得改（确有取舍时）。
- 原代码位置、P/I 引用、验证状态、剩余缺口。

### 行为契约

| 操作/参与者 | 输入与前提 | 结果及后置条件 | 失败/取消/重试 | 责任模块与证据 |
|---|---|---|---|---|

### 核心伪代码

每块 P01、P02……保留实际标识符与关键顺序。标明属于当前实现还是建议方案。

### 不变量与验证

| ID | 要维持的性质及来源 | 实施机制/代码 | 测试与具体断言 | 验证状态/缺口 |
|---|---|---|---|---|

没有测试时写明缺失。测试文件存在、断言相关、已经执行通过分别说明。

### 资源、数据与权限

只保留本次相关维度。逐项给出 owner、边界/预算、正常结束与失败处理、证据位置；不适用项一句依据即可。

## 代码映射与全貌

### 正向映射

| 解释 ID | 文件/符号 | base 或 head 的行区间 | 快照 SHA | 定位链接 |
|---|---|---|---|---|

行区间是文字字段；链接指向实际起始行。删除逻辑引用 base。一个解释块对应多处实现时列齐；必要的未改调用方标为“上下文”。

### 反向账本

| Hunk ID | 路径及旧/新范围 | 解释 ID 或豁免依据 | 状态 |
|---|---|---|---|

计数口径：完整 diff 中唯一 hunk 数 H，已解释 E、有依据豁免 X、未解释 U，H=E+X+U。一个 hunk 映射多个 P 仍只算一次；混合 hunk 未全部处理时归 U。

- 完整清单的记账覆盖率：(E+X)/H；H=0 时不适用。
- 需要解释的 hunk 映射率：E/(H-X)；H-X=0 时不适用。
- 截断/缺失文件：只报告已见部分数量，整体分母与比例未知。
- 未解释列表必须可定位，不能靠缩小分母消失。

这些数字只说明变更有没有解释或分类，不衡量测试覆盖或设计正确性。

## 人的阅读与排查路线

给出按顺序打开的少数位置，以及每一步要看什么。例如：

“从入口看 actor 和请求 ID；到决策函数看是否进入拒绝分支；到存储看提交结果；到通知层看发送状态；最后看 UI 用了哪个状态字段。”

具体函数、日志、运行与测试命令取自实际仓库。说明预期值与能推翻解释的观察结果。需要运行才能回答的问题，列出最小验证动作和当前状态。

## 验证边界

- 静态已核实的链路与引用。
- 实际运行的命令、快照、结果及适用范围。
- 未解释的变更、待验证主张、需要人决定的业务取舍。
- 交付前 head 回读结果；过时则显式注明。

最后用具体场景写出“为什么这样设计 / 某次失败会怎样 / 应到哪里定位”的答案，使读者能自行检查理解。
